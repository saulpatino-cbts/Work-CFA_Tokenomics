# UI concepts

**Status:** concept drawings, not an implemented UI. **[REVIEW REQUIRED]** Brand approval is pending. All values are synthetic and no provider was contacted.

Files: [`design/concepts/`](../design/concepts/) holds static HTML (`telemetry.html`, generated by `build_telemetry.py` from a fixed synthetic seed, and `setup.html`), shared tokens (`tokens.css`) and rendered images (`images/`). Re-render with Playwright at 1440 px wide.

## Telemetry view

The first draft was a summary slide. The telemetry concept replaces it and shows where tokens are spent: filters (range, vendor, SKU type, model, project or key, source); one counter and sparkline per token category (input, output, cache read, cache write, reasoning) with no combined total; an hourly time series per vendor with a "not yet reported" region; spend by vendor and SKU (API on-demand, API provisioned, subscription seats); a weekday-by-hour heatmap; top consumers with how each is attributed; a breakdown table by vendor, SKU, source and reconciliation state; cache activity as separate counts; and a sources-and-freshness table that separates vendor admin APIs, cloud telemetry and app-routed requests.

Categories are never stacked into one total because providers define cache and reasoning tokens differently ([token accounting](token-accounting.md)). Series differ by line style and marker as well as colour.

## Source and rules applied

Built from the CBTS Brand Guidelines v1.10 (colour pp. 24-30, typography pp. 34-36, design system pp. 52-61); other sections were not read. Applied: the primary palette as transcribed in `tokens.css`; the secondary palette only inside the chart; rounded corners on every visible edge (14px, 1.5% of the shortest side); 38px margins (3.7%); dark teal/dark blue title blocks and light supporting blocks; hex-dot background on Light Gray; no gradient fills; Bright Teal only as a highlight; flush-left text.

Product rules applied: provider and app figures are never added; the app figure is shown inside the provider figure; unknown is "unknown", never zero; the unattributed gap is counted only for fully reconciled models; every total sits next to its freshness; status never relies on colour alone.

## Placeholders and open questions

- **Logo:** placeholder only; the real logo asset has not been supplied or read from the guide.
- **Typeface:** Aeonik and Eurocat are licensed and not bundled. Images render with Inter as a stand-in. Licence and redistribution rights are unconfirmed (brand to confirm).
- **Product name:** "CFA Tokenomics" is the repository's working name, not an approved product name.
- **Hex-dot colour:** the guide says Dark Gray in text and Gray in a callout; the concepts use Gray.
- **Vendors, SKUs and ingestion APIs:** the vendor names, SKU types and attribution dimensions (per key, project, resource) are illustrative. The required integrations are still Foundry, Bedrock and Vertex AI ([providers](providers.md)); direct vendor admin/usage APIs and subscription SKUs are **not yet in scope** and need an owner decision and per-vendor verification of what each API reports.
- **Subscription SKUs:** shown as "not reported" because seat plans are usually not token-metered. Unverified per vendor.
- **Chart contrast:** some secondary-palette lines (for example lime on white) are low contrast; lines also use dashes and markers. Needs an accessibility review.
- **Not drawn:** role and account management, Assessment, export/import, error states, mobile.
- **Figma:** not used; the connector was not enabled in this session.
