# 6. UX and dashboard redesign

**Status:** proposed. Part of the [AI economics redesign](README.md). Supersedes the token-first concepts in [`design/concepts`](../../design/concepts/) and [UI concepts](../ui-concepts.md), which stay in history. Brand rules from the CBTS guide still apply, and branded screens still need human brand approval.

## Principles

- **Economics first, tokens underneath.** The home screen shows money, value and decisions. Tokens appear only in drill-down.
- **Every number has a basis badge** (observed, estimated, assumed) and opens the explain view.
- **Assumptions are visible and editable**, never buried in a formula. Changing one recalculates live and is audited.
- **Provisional data is marked** (hatched), and the share of a figure that rests on assumptions is stated.
- **Unknown is "not reported", never zero.** Sources are never added together.
- One design system, accessible by default (keyboard, labelled charts, tables as alternatives).

## Executive overview: the ten questions

| Question | Widget |
| --- | --- |
| 1. What are we spending? | Total AI cost this period, trend, budget variance (with basis mix). |
| 2. What is causing the spend? | Drivers: model, provider, infrastructure, licence, labour; change versus last period. |
| 3. Which applications consume it? | Ranked applications with cost share and allocation coverage. |
| 4. What value are they generating? | Value per application, capacity and cashable shown separately. |
| 5. What is the effective unit cost? | Cost per transaction, interaction, user and outcome, with trend. |
| 6. What is the ROI? | ROI and payback per application and in total; assumption-dependence flag. |
| 7. What happens as usage scales? | Scenario preview: cost, ROI and margin at 2× and 10× usage. |
| 8. Where can costs be optimized? | Ranked levers (model change, caching, commitment, rightsizing) with estimated saving. |
| 9. What should we charge a customer? | Required price at the target margin for selected applications. |
| 10. What margin would that produce? | Gross margin at the proposed price after marketplace fees. |

Tokens never appear on this screen except as a labelled driver in question 2.

## Screens

1. **Executive overview.** The table above.
2. **Portfolio.** Applications as rows: cost, value, ROI, unit cost, margin, basis mix, allocation coverage, data finality. Filter by business unit, customer, environment, provider, cloud, model, period.
3. **Application detail**, tabs:
   - *Economics:* waterfall from Total Cost of Application to value to net value, with ROI and payback.
   - *Cost:* breakdown (AI, infrastructure, licences, operations, amortized build) and the allocation view.
   - *Usage and tokens:* **the former telemetry page lives here**, as a drill-down.
   - *Value model:* the assumption editor.
   - *Unit economics.*
   - *Scenarios.*
   - *Pricing.*
   - *Provenance.*
4. **Value model editor.** A table of assumptions with value, unit, basis badge, rationale, author and version; live-updating results beside it; capacity versus cashable toggle; history and revert.
5. **Scenario studio.** Columns for Baseline, Current, Forecast, Optimized and Customer Proposal side by side; a driver panel (users, adoption, interactions per user, tokens per interaction, model mix, cloud rates, commitment, labour rate, price); tornado chart and two-way grid for sensitivity; "promote to proposal".
6. **Pricing and marketplace studio.** Price-model editor (subscription, per user, usage, per transaction, token-based, application, tiered, customer-specific); cost-to-run versus price versus margin chart; required price for a target margin; break-even volume; marketplace fee schedule and commitment-drawdown settings; customer proposal export.
7. **FinOps workbench.** Allocation rules and results, tag coverage, the unallocated bucket, budgets and forecast, anomalies, showback and chargeback statements.
8. **Sources and connector health.** Connector list with credential status, lag, last success, errors, schema drift; onboarding wizard with the permission checklist ([connectors](04-connectors.md)); manual import.
9. **Explain view.** A drawer opened from any number: figure, calculation (formula ID and version), inputs with basis, source records, ingestion run and timestamps, price-book version.
10. **Administration.** Roles and grants, business units, retention policies, audit log, API keys.
11. **Reports and exports.** Scheduled and on-demand reports, CSV and FOCUS-format exports, an API for the same data.

## Key workflows

- **Onboard data:** add a connector or import a file, validate, see the first rows, confirm allocation coverage, see an application's first cost.
- **Build the case:** create an application, attach cost sources, enter value assumptions, read the economics, trace any figure.
- **Scale and optimize:** clone Current to Forecast, change drivers, compare, apply an Optimized lever.
- **Sell it:** pick an application, set a price model and marketplace fees, solve for the target margin, create a Customer Proposal scenario, export.

## What happens to the existing screens

The telemetry page becomes the Usage tab. Its category counters, series, heatmap and reconciliation table are kept; it gains the basis badge and finality marking. The setup wizard concept is replaced by connector onboarding.

Behaviour worth knowing:

- The value model **is** the scenario input: assumption keys are the scenario driver names, so the editor and the Economics tab cannot disagree.
- Opening Economics runs a calculation, which stores its record and writes an audit event. Because of that, readers see the value model and stored explanations but cannot run a calculation.
- A banner states the share of the headline net value that rests on assumptions, and turns to a warning past half.
- Basis is shown by symbol, wording and border style, never by colour alone. The explain drawer is a labelled dialog that closes with Escape and returns focus.
- Cost and allocation shows tenant-wide coverage only; the API does not yet report cost per application.
- Amounts are kept as strings from the API to the screen and back; only the display formatting converts them to numbers.

Not yet tested: a real browser session against a real identity provider, a screen reader pass, and mobile layouts beyond a basic breakpoint.
