# 9. Vendor API research (Phase 2 preparation)

**Status:** research notes, compiled 2026-11-10. Part of the [AI economics redesign](README.md). They refine the capability matrix in [connectors](04-connectors.md) and answer the *not found* items in risk R-16 and R-21. **Nothing here has been run:** no API was called, no sample response was obtained, and no account was used.

## How to read this

- Researchers read official vendor pages only (vendor documentation sites and vendor changelogs) and reported what each page said. Page text was treated as data. A second reader has not re-checked these notes, and each connector still needs the checks in [Adding a provider](04-connectors.md#adding-a-provider) and an authorized integration test before it is marked supported.
- **NOT FOUND** means the answer was not on the pages tried. It does not mean the feature is absent.
- **(search)** marks a claim that came from a web-search summary rather than a page the researcher read. Treat it as a lead, not a fact.
- **[PII]** marks a field or endpoint that identifies a person. **[VERIFY]** marks a figure that must be re-checked before use. Prices and allowances change and are often customer-specific: never hard-code them.
- Many pages show no "last updated" date, and several were partly read (the tool cut long pages off). Each section says where.

## What changed our design assumptions

| Finding | Effect |
| --- | --- |
| Microsoft bills **Claude in Foundry** through one Azure Marketplace *Claude Consumption Unit* meter, attached to the Foundry resource and its tags, not through per-model token meters. | Cost for Claude on Azure arrives in the Azure FOCUS export as CCU, and tokens only explain it. Attribution is by resource tags; project-level attribution is not supported for Claude. |
| **Third-party Bedrock models** (for example Anthropic) are billed through AWS Marketplace and appear in the AWS bill under the model provider, not under Amazon Bedrock. | Do not filter AWS cost by service name alone. Discover service names with `GetDimensionValues`. |
| **AWS Cost Explorer gained Bedrock product attributes** (announced 2026-10-08): `provider`, `model`, `inferenceType` (input or output tokens) and `feature`. Only periods from 2026-09-01. | The first AWS source that splits Bedrock cost by model and token direction without CUR parsing. Earlier periods need CUR or FOCUS. |
| **OpenAI cost amounts are JSON numbers**, not strings (`amount.value`). | Parse the raw JSON text into Decimal. A float parser would break the exact-money rule. Anthropic sends decimal strings, which is safer. |
| **GitHub replaced premium requests with AI Credits on 2026-06-01** (1 credit = $0.01, token-based). The legacy Copilot metrics APIs were retired in March and April 2026. | Model Copilot spend in credits and net amounts, not request counts. Use only the new usage-metrics reports. |
| **Azure's FOCUS export is still 1.2-preview**; AWS offers FOCUS 1.2 and 1.0 only; Google offers a FOCUS export in **preview** with an unstated version. | The importer's version handling is right: process by column name. Do not assume 1.4 columns from any cloud. See [FOCUS 1.5 readiness](08-focus-1-5-readiness.md). |
| **Perplexity and the Gemini Developer API have no organization usage API** in the pages read. Gemini cost is Cloud Billing; Perplexity is console and per-response only. | Both are manual import or gateway telemetry until a vendor API appears. Do not promise a connector. |
| Several vendor APIs return **emails or logins**: Anthropic Claude Code analytics and spend limits, GitHub per-user reports, Microsoft Copilot user detail, OpenAI user-grouped usage, Claude Code OpenTelemetry (`user.email`). | Privacy defaults in [R-17](../risk-register.md) apply to every one: aggregate by default, pseudonymize references at ingest, never ingest bodies. |
| Some sources carry **prompt and response content** by design: Bedrock invocation logs, Vertex request-response logging, Microsoft Copilot interaction export, the OpenAI Compliance API. | Never connect them. Token counts come from metrics instead. |

## Anthropic and Claude Code

Sources: `platform.claude.com/docs/en/manage-claude/` pages `usage-cost-analytics-api`, `usage-cost-api`, `analytics-api`, `claude-code-analytics-api`, `user-management`, `spend-limits-api`; `code.claude.com/docs/en/monitoring-usage` (first 100,000 of about 174,000 characters read) and `.../costs`. No page showed a date.

- **Usage and Cost Analytics API (beta).** `GET /v1/organizations/analytics/usage` and `.../analytics/cost`, header `anthropic-beta: analytics-usage-cost-2026-08-24` plus `anthropic-version`. The docs say to use it for new integrations. The legacy `usage_report/messages` and `cost_report` endpoints are "legacy and remain supported", not deprecated.
- **Auth.** Console: an Admin API key, an `org:admin` OAuth token, or a personal or service-account key that is not workspace-scoped. Enterprise: an Analytics key with scope `read:analytics`, created by the Primary Owner.
- **Freshness and revision.** Typically within 4 hours, up to 24. Every response has `data_refreshed_at`. Values are **revised until about 7 days after calendar month end**, so final totals need months that ended at least 7 days ago. The legacy API is typically within 5 minutes.
- **Limits.** `starting_at` on or after 2026-01-01 and within 365 days; at most 31 days per request, 24 hours with 1m buckets; `limit` 1 to 1,000 (default 20), cursor-bound `page`/`next_page`; `group_by[]` up to 5 dimensions. **Rate limit: 60 requests per minute per organization** for the Analytics API; Admin API endpoints share 100 per minute.
- **Cost semantics.** `amount` is after discounts and before credits; `list_amount` is list price. Both are decimal strings in cents with six decimals, USD. **Priority Tier** requests show in usage with zero token cost; the commitment fee is billed separately and is **not in this data**. Code execution appears with `model: null`.
- **Claude Code Analytics API.** `GET /v1/organizations/usage_report/claude_code?starting_at=YYYY-MM-DD`, one UTC day per request, several records per actor per day (sum them). Fields: sessions, lines of code, commits, pull requests, tool accept and reject counts, and per-model tokens (input, output, cache read, cache creation) with `estimated_cost` in cents. **[PII] `actor.user_actor.email_address`.** Console-authenticated usage only: it **excludes Claude subscription sign-ins and Bedrock, Vertex and Foundry usage.**
- **Claude Code OpenTelemetry.** Metrics include `claude_code.token.usage` (`type` is `input`, `output`, `cacheRead` or `cacheCreation`) and `claude_code.cost.usage` (USD); the `api_request` event carries `cost_usd_micros` and token counts. **[PII] `user.email` is always attached when available; `user.account_uuid` defaults on.** Prompt, response, tool-detail and raw-body logging are opt-in and off by default. Claude Code shows list-price estimates, not invoices.
- **Enterprise and Team.** Enterprise has member, spend-limit (`/v1/organizations/spend_limits/effective`, scopes `read:spend_limits`) and per-user Analytics endpoints, all [PII]. A Team API for seats, limits or usage was **NOT FOUND**; the docs point to a per-user CSV in the admin console. Usage inside a seat allowance is not metered in dollars.
- **Bedrock, Vertex and Foundry.** Anthropic's APIs do not cover that usage; the cloud bill is the cost source. Exceptions: Claude Platform on AWS and Claude Models on Google Cloud (Anthropic managed), where parts of the Anthropic API apply.
- **NOT FOUND:** the full `cost_type` value list, the batch discount mechanics inside `amount`, a numeric history limit for the Claude Code API, and a Foundry-specific billing page on Anthropic's side.

## OpenAI and Codex

Sources: `developers.openai.com/api/reference/resources/admin/.../usage` (completions, costs), the completions-usage cookbook and audit-logs pages; `learn.chatgpt.com/docs/enterprise/` pages (governance, workspace-analytics, analytics-api, compliance-api) and `/docs/pricing`, reached through redirects from `developers.openai.com`. Several `help.openai.com` pages returned 403 and were not read.

- **Usage and costs APIs.** Admin key required. Usage endpoints for completions, embeddings, moderations, images, audio, vector stores, code interpreter, file searches and web searches. Completions fields include `input_tokens`, `input_cached_tokens`, `input_uncached_tokens`, `input_cache_write_tokens` (with `_30m_` and `_12h_` variants), per-modality tokens, and `num_model_requests`.
- **Grouping and paging.** `group_by`: `project_id`, `user_id`, `api_key_id`, `model`, `batch`, `service_tier`, `api_source` (`agents_api` or `unlabeled`). Usage `limit` by bucket: 1d max 31, 1h max 168, 1m max 1,440. **Costs: `1d` buckets only**, `limit` 1 to 180, `group_by` including `line_item`.
- **Cost object.** `organization.costs.result`; **`amount.value` is a JSON number**; `amount.currency` is lowercase (`"usd"`); `quantity` and `quantity_unit` (`tokens`, `1000_tokens`, `duration_seconds`, `gibibyte_hours`, `images`, `characters` and others) are filled when grouped by `line_item`.
- **NOT FOUND:** data delay and revision rules, retention, rate limits, and usage-specific key scopes. Design defensively until measured in a test organization.
- **Codex.** A unified **Daily Usage Analytics API** covers ChatGPT, Codex and Work usage for a workspace. It needs a workspace-scoped Admin key with permission **`enterprise.analytics.usage.read`**; the Codex scope `codex.enterprise.analytics.read` does **not** grant access to it. **Endpoint paths, methods, fields, window, pagination, limits, delay and Enterprise-only status are NOT FOUND:** the conceptual pages defer to an Admin API reference at `chatgpt.com/public/admin/api-reference`, which renders only in a browser. **Open item:** someone with a browser should download that reference's OpenAPI file and add it to the repository's fixtures.
- **Compliance API.** Audit records, not usage analytics: `conversation_message` and `codex_log` types, a `COMPLIANCE_API_KEY`, an `after` filter. **It holds conversation content, so it must not be connected.** A "30 days" retention figure appeared only in a search summary (search) and is unverified.
- **Codex seats and credits.** Codex and ChatGPT Work share usage, credits and limits. Codex used with an API key is billed at API pricing and so appears in the OpenAI costs API. Credits are priced per million tokens (input, cached input, output), with fast-mode multipliers of 2x and 6x for purchased credits **[VERIFY: prices and rates change]**. A credit-balance API was **NOT FOUND**. Local Codex execution emits OpenTelemetry events through an operator-configured collector.

## GitHub Copilot

Sources: `docs.github.com` pages for usage metrics, user management, billing usage and billing concepts, plus the GitHub changelog. API version header `X-GitHub-Api-Version: 2026-03-10`. Parts of one long reference page were not read.

- **Usage-metrics reports.** Under `/enterprises/{enterprise}/copilot/metrics/reports/` and `/orgs/{org}/copilot/metrics/reports/`: `*-1-day` (required `day=YYYY-MM-DD`), `*-28-day/latest`, and `users`, `user-teams` and `repos` variants. Responses are `download_links` to report files. Permissions: fine-grained "View Enterprise Copilot Metrics" or "View Organization Copilot Metrics" (classic `manage_billing:copilot`, `read:enterprise`, `read:org`). GitHub App permissions: **NOT FOUND**. History from 2025-10-10 up to a year. Freshness: **NOT FOUND**.
- **Report contents.** **[PII] `user_login` and `user_id`** in per-user files. Interaction, code-generation and acceptance counts, lines suggested and added, `ai_credits_used` (a total only, not by model, and not for invoicing), and breakdowns by IDE, feature, language and model. **Token counts exist** in some breakdowns (CLI, client and model: prompt, output, average per request). Model breakdowns are chat only, and bring-your-own-key token sums can undercount.
- **Seats.** `GET /orgs/{org}/copilot/billing` and `.../billing/seats` (public preview): seat counts, `plan_type`, `last_activity_at`, `last_activity_editor`, `pending_cancellation_date`. `per_page` max 100.
- **Billing.** `GET /organizations/{org}/settings/billing/ai_credit/usage`, `.../premium_request/usage`, `.../usage` (enhanced billing platform) and `.../usage/summary` (public preview). Query by `year`, `month`, `day`, `user`, `model`, `product`. Items carry `product`, `sku`, `model`, `unitType`, `pricePerUnit`, and gross, discount and net quantity and amount. Org administrator required; 24 months of history. Allowances presumably show as the discount: that is an inference, not stated.
- **Pricing change.** **AI Credits replaced premium requests on 2026-06-01** (1 credit = $0.01; token-based). Business includes 1,900 credits per user per month and Enterprise 3,900 in an org-wide pool that resets monthly; promotional amounts ran 2026-06-01 to 2026-09-01 (search). **[VERIFY]** Legacy request billing remains only for some annual Pro and Pro+ plans.
- **Retired:** the legacy Copilot Metrics API on 2026-04-02, and the user-level feature engagement and direct data access APIs on 2026-03-02.
- **Limits.** No Copilot-specific limit found. General REST: 5,000 requests per hour per personal token, at least 5,000 per hour (15,000 on Enterprise Cloud) per app installation, and secondary limits.

Sources: `learn.microsoft.com` Microsoft 365 Copilot extensibility (Graph reports, interaction export, cost management), Viva Insights, Entra licensing and Graph throttling pages (most dated 2026), and the public pricing page. The licensing reference was read only to its first 100,000 of 843,000 characters.

- **Usage reports.** Now documented under **`/copilot/reports`** in both v1.0 and beta (the old `/reports` path is superseded). Methods: `getMicrosoft365CopilotUsageUserDetail` **[PII]**, `getMicrosoft365CopilotUserCountSummary`, `getMicrosoft365CopilotUserCountTrend`, and a `...UserDetailByDate` method that was not read. `period` D7, D30 (v1) or D28 (v2), D90, D180, ALL; `version` v2 is the default. v1.0 returns CSV, beta returns JSON.

- **Licence.** SKU string `Microsoft_365_Copilot` ("Copilot for Microsoft 365"), GUID `639dec6b-bb19-468b-871c-c5c441c4b0cb`. The Business-tier SKU and any Copilot Chat or pay-as-you-go SKU were **NOT FOUND**.
- **Price.** The pricing page showed a Copilot Business add-on at $18.00 per user per month on yearly billing (a promotion, first year, to 2026-12-31) and $25.20 monthly, and bundles at higher prices **[VERIFY]**. The enterprise price was **NOT FOUND**. **No API returns the seat price**; it must come from the customer's price book or invoice.
- **Metered agents and credits.** Chat and Copilot Studio pay-as-you-go bills to a linked Azure subscription through Azure meters (Copilot Studio listed at $0.01 per message **[VERIFY]**); whether it appears in Cost Management as expected was not verified. A **beta Copilot Cost Management API** at `/beta/copilot/costManagement` reports **credits only, no currency or price**: user usage records **[PII]**, group usage, service usage, funding usage (monthly), user detail and sessions **[PII]**, and tenant credit balance. Permissions `CopilotCostManagement-Reports.Read.All`, `CopilotCostManagement.Read.All`, `CopilotCostManagement-UserData.Read.All`; most operations are delegated-only.
- **Viva Insights Copilot Dashboard.** Dashboard, Agent Dashboard, Consumption Dashboard (Copilot Credits and GitHub AI Credits), and Power BI Advanced Reporting (needs the Insights Analyst role). Export is a **preview, browser-only button** with anonymized IDs by default; **no export API was found**. Group-size minimums suppress small groups.
- **Interaction export.** `getAllEnterpriseInteractions` (application-only `AiEnterpriseInteraction.Read.All`) **returns prompt and response text** and needs a Copilot licence. **Do not use it.** Counts can come from the reports instead.

## AWS

Sources: `docs.aws.amazon.com` (Cost Management API reference, Data Exports and CUR user guide, Cost Management user guide, billing example policies, Bedrock user guide and the Claude Sonnet 5.5 model card, CloudWatch API reference) and `aws.amazon.com` pricing, FAQ and "What's New" pages.

- **Cost Explorer.** Granularity `DAILY`, `MONTHLY`, `HOURLY` (hourly is opt-in and covers the past 14 days). Up to 2 group-by keys. `GetCostAndUsageWithResources` is opt-in, limited to 14 days, and its resource-level hourly data is EC2 only, so **it does not give Bedrock resource-level cost**. History: 13 months plus the current month (guide). **$0.01 per paginated request.** Rate limits: **NOT FOUND**.
- **Bedrock product attributes (new, October 2026).** Keys `provider`, `model`, `inferenceType` ("Input tokens" or "Output tokens"), `feature`, used in `Filter.ProductAttributes` and `GroupBy Type=PRODUCT_ATTRIBUTE`. Periods from 2026-09-01 only (earlier returns `DataUnavailableException`). Bedrock only; costs can appear under several service names, so omit the service filter. No extra charge; not in GovCloud or China.
- **Usage-type strings (CUR).** `{region}-{model}-{token-type}[-{tier}]`: `*-input-tokens`, `*-output-tokens`, `*-cache-read-input-token-count`, `*-cache-write-input-token-count`, with `-cross-region-global` and tier suffixes. **All four token types must be summed or totals will not match the bill.**

Refresh: at least once a day (whether more than once is unclear). The previous period may be updated for the first two weeks; `manifest.json` points to the latest run; a "finalized" flag was **NOT FOUND**. FOCUS 1.2 has `x_Discounts`, `x_Operation`, `x_ServiceCode` and the standard `Tags` map, but **no usage-type column** (that is in FOCUS 1.0 as `x_UsageType`, or CUR 2.0 `line_item_usage_type`).
- **Marketplace-sold models.** The model card says Claude Sonnet 5.5 is offered and billed through AWS Marketplace and "appears on your AWS bill and in Cost Explorer under the model provider (not under Amazon Bedrock)". The literal `ServiceName`, `ChargeCategory`, `PublisherName` and `InvoiceIssuerName` values were **NOT FOUND**.
- **CloudWatch.** `GetMetricData`: up to 500 queries per call, 100,800 datapoints default. Retention: 1-minute data 15 days, 5-minute 63 days, 1-hour 455 days. Price per metric: **NOT FOUND**.
- **Invocation logging.** S3 (gzipped JSON) and CloudWatch Logs; schema `ModelInvocationLog` 1.0 with `identity.arn`, optional `requestMetadata` (up to 16 entries), `inputTokenCount` and `outputTokenCount`; bodies over 100 KB go to separate S3 objects. Whether bodies can be fully switched off while keeping token metadata, and cache-token fields in the schema, were **NOT FOUND**. The docs contradict each other on joining logs to CUR by `requestId`: treat joins as model, usage type and day grain. **Not connected, because the logs hold bodies.**
- **IAM.** `cloudwatch:GetMetricData` and `cloudwatch:ListMetrics` are verified. The Cost Explorer example policy uses `ce:*`. **Unverified:** `ce:<Operation>` names, the `bcm-data-exports:*` read actions, and the `s3:GetObject` and `s3:ListBucket` actions on the export bucket; all must be confirmed against the Service Authorization Reference.
- **Budgets and anomaly detection.** Budgets can filter by Bedrock product attributes (October 2026 announcement; API shape **NOT FOUND**), updating up to three times a day. Anomaly Detection supports third-party Bedrock models, needs 10 days of history and analyses only usage charges at net unblended cost; a Bedrock-specific API was **NOT FOUND**.

## Azure and Foundry

Sources: `learn.microsoft.com` (Cost Management dataset schema, exports, `manage-automation`, Foundry cost and Claude billing pages, monitoring references, API Management policy, Retail Prices API, built-in roles, analyze-unexpected-charges). Most pages are dated 2025 to 2026. The roles page was read only in part.

- **FOCUS export.** "Cost and usage details (FOCUS)" is **1.2-preview**, 105 columns including `x_` columns, for EA and MCA scopes. **No management-group scope and no pay-as-you-go (MOSP) support.** CSV (none or gzip) or Parquet (none or snappy), files under 1 GB each, partitioning cannot be disabled, a `manifest.json` per run. Available within 4 hours of a run; a daily export runs twice a day for the first five days of a month, and latent charges can land up to 72 hours after month close.
- **Query API limits.** Quotas per tenant in query processing units: 12 per 10 seconds, 60 per minute, 600 per hour (about one unit per month of data queried; may change). `429` with `x-ms-ratelimit-microsoft.costmanagement-qpu-retry-after`, `-consumed` and `-remaining`. The docs advise calling no more than once a day, since data refreshes every 4 hours. **Exports are the recommended bulk route**; the asynchronous Cost Details API is the alternative (EA and MCA; use exports above about 2 GB a month). Lookback: exports up to 7 years via the Execute API; portal 13 months.
- **Azure OpenAI and Foundry in cost data.** Billed by Microsoft as input and output meters under each Foundry resource (`Microsoft.CognitiveServices/accounts`), classed as Cognitive Services. Split by deployment with deployment tags. **Exact `MeterCategory`, `MeterName` and `ServiceName` strings were NOT FOUND**: derive them from the customer's own export or the Retail Prices API.
- **Claude in Foundry.** Billed in **Claude Consumption Units** through Azure Marketplace (offer "Claude Platform on Foundry"): one CCU meter, hourly metering, invoiced monthly in arrears, MACC-eligible, converted from tokens by Anthropic's published rates after Marketplace private-offer discounts. Charges attach to the Foundry resource, carry its tags, and break down by model and usage type. **Project-level attribution is not supported for Claude.** Deployments created before CCU keep per-model token billing. CSP subscriptions cannot buy partner models. The literal `ChargeCategory`, `PublisherName` and FOCUS `ServiceName` values for these rows were **NOT FOUND**.
- **Token metrics.** `FoundryModelEstimatedCost` is **preview** and not exportable to logs. Metrics include `InputTokens`, `OutputTokens`, `TotalTokens` and Claude cache metrics (`cacheReadInputTokens`, `ephemeral5mInputTokens`, `ephemeral1hInputTokens`). **No per-caller dimension exists.** The documented attribution route is the API Management policy `llm-emit-token-metric` (custom dimensions up to five, 100 values each, 1,000 active series; overflow is silently dropped), or one deployment per application.
- **Logging.** Diagnostic categories include `Audit`, `AzureOpenAIRequestUsage` and `RequestResponse`, off by default, up to 2 hours of delay. Whether `RequestResponse` contains bodies is **NOT FOUND** in official pages (community posts say yes; unverified). Treat it as containing bodies.
- **Prices.** The Azure Retail Prices API (`prices.azure.com/api/retail/prices`, no authentication, 1,000 records per page) covers Azure meters; an AI-meter example was **NOT FOUND**.
- **Roles.** Cost Management Reader (`72fafb9e-0641-4937-9268-a91bfd8191a3`), Cost Management Contributor (`434105ed-43f6-45c7-a02f-909b2ba83430`), Billing Reader (`fa23ad8b-c56e-40d8-ac0c-ce449e1d2c64`). The Monitoring Reader ID and a read-only storage role for the export were **NOT FOUND**: the export tutorial grants the export's own identity `StorageBlobDataContributor`.
- **Budgets and anomalies.** Consumption Budgets API (`Microsoft.Consumption/budgets`), evaluated daily; anomaly detection is subscription scope only, daily on a 60-day baseline, email delivery, created through the Scheduled Actions API (`InsightAlert`). **No API to read anomaly results was found.** No hard budget cap exists for Azure OpenAI.

## Consequences for Phase 2

1. **Order stays: cost authority first.** Azure and AWS exports (cost), then Anthropic (the clearest vendor cost and usage API), then Bedrock and Foundry metrics (drivers), then GitHub Copilot, OpenAI, and Microsoft 365 Copilot. Vertex AI has two real routes (Monitoring and the BigQuery billing export). Perplexity and the Gemini Developer API stay manual import or gateway telemetry.
2. **Codex is blocked** on the Admin API reference. Until someone supplies it, Codex spend is covered only where it is billed through the OpenAI costs API (API-key use) or imported manually.
3. **Microsoft 365 Copilot has no cost API in dollars.** Seats come from `subscribedSkus` and the customer's price book; activity from the usage reports (names concealed); credits from the beta Cost Management API (credits only, mostly delegated and per-user). The unit economics stay per licensed user, never per token.
4. **Privacy decision before any per-user source.** Anthropic, GitHub, Microsoft, OpenAI user grouping and Claude Code OpenTelemetry all identify people. The default must be aggregate ingestion with pseudonymized references, and per-user data only with an explicit, recorded customer opt-in (R-17).
5. **Never connect a content-bearing source:** Bedrock invocation logs, Vertex request-response logging, the Copilot interaction export, the OpenAI Compliance API, and Azure `RequestResponse` logs.
6. **Money parsing.** OpenAI cost numbers must be parsed from raw JSON as decimals; Anthropic strings are already decimal. Do not use a float JSON parser on any cost response.
7. **Revision windows differ** (Anthropic about 7 days after month end, Azure up to 72 hours after month close, AWS two weeks, Microsoft 24 to 72 hours), so each connector must set `finality` from the source's own rule, not one global rule.
8. **Prices and allowances are volatile.** GitHub and Microsoft changed pricing within the last six months. Seat price, included credits and rate cards belong in the customer-editable price book with an effective date, never in code.
