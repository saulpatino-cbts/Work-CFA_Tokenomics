# Changelog

Record notable changes under Unreleased in the same PR. No product release or runtime support is established by this file. Versioning policy must be confirmed before the first software release.

## [Unreleased]

### Changed

- **Breaking: admin-only roles (ADR 0013).** The roles are now `admin` and `finance_viewer` (read-only). `user` and `reader` are removed; existing assignments become `finance_viewer` (migration 0010). Replace `CFA_OIDC_USER_GROUP` and `CFA_OIDC_READER_GROUP` with `CFA_OIDC_FINANCE_GROUP`. Economics writes are admin-only. ADR 0012's aggregate-by-default privacy rule is superseded; per-user cost is a core view (per-user connector mode is not built yet).

### Added

- People mapping and display choice (ADR 0013, migration 0011): a `people` table (pseudonym to name only), a per-tenant `person_display` setting (`pseudonym` default, or `name`), `GET /v1/people/resolve`, admin-only `PUT /v1/admin/people/display`, and the `people-import` and `person-display` operator commands. Switches and name lookups are audited as counts. Not yet built: directory sync (Entra ID, Google) and the per-user connector mode.

- Customer-hosted product requirements with stable REQ IDs and an indexed documentation set.
- Architecture, customer roles/identity, scoped Assessment, provider integration, and token-accounting contracts.
- Deployment/onboarding, full portability, customer-owned lifecycle, operations, and acceptance-test documentation.
- Delivery roadmap, design risk register, and three accepted product-boundary ADRs.
- Root agent instructions for implementation and review.

- API skeleton in `apps/api` (FastAPI health endpoints, configuration validation, deny-by-default role matrix, unit tests), skeleton Dockerfile, development-only compose file, and `.env.sample`.
- OIDC bearer-token verification (signature, issuer, audience, expiry, asymmetric algorithms only), IdP-group-to-role mapping, and a customer-set bootstrap admin identity; production config now requires an admin path. Dependencies PyJWT 2.15.1 and cryptography 50.0.2 pinned and checked with pip-audit.
- PostgreSQL layer (ADR 0006): role-assignment and audit tables, Alembic migration `0001` (`python -m cfa_tokenomics.migrate`), `PUT/DELETE /v1/admin/roles` with audit events and last-admin protection, database-aware `/readyz`. Effective role is the highest of bootstrap, IdP group and stored assignment. Tests run against real PostgreSQL when `CFA_TEST_DATABASE_URL` is set. SQLAlchemy 2.1.8, Alembic 1.20.1, psycopg 3.3.8 pinned and checked with pip-audit.
- Usage ledger (ADR 0007): request and aggregate observation tables with checkpoints (migration `0002`), idempotent request writes, revision-tracked aggregate windows, reconciliation rules that never add sources, adapter contract, and a Bedrock CloudWatch metric normalizer. Tests use labeled synthetic data only; no provider has been called.
- `GET /v1/usage` returns reconciled usage for a required, bounded time range (reconciliation status, app-observed, provider-reported, unattributed, partial flag, aggregate quality and revision, collection freshness). `GET /v1/whoami` is a database-free authentication check. Account scoping (ADR 0008, proposed): admins see all accounts; users and readers see only (provider, account) pairs granted to their identity via `PUT/DELETE /v1/admin/grants` (audited, migration `0003`). No grant means no data. Workspaces and group-based scoping are not implemented.
- UI concept drawings (token telemetry view and setup wizard) with brand tokens, static HTML and rendered images under `design/concepts/`, and `docs/ui-concepts.md`. Concepts only; brand approval pending.
- SKU and source dimensions (ADR 0009, proposed): `sku` (`api_on_demand`, `api_provisioned`, `subscription`, `unknown`) and `source_type` (`cloud_telemetry`, `vendor_admin_api`, `app_routed`) on all observations (migration `0004`; existing rows become `unknown`), `sku`/`source_type` filters on `GET /v1/usage`, and `GET /v1/usage/series` (one category per query, hour or day buckets, grouped by vendor/SKU/model/account, sources never added, windows longer than the bucket excluded and counted). No vendor admin API adapter yet.
- Web app in `apps/web` (React, TypeScript, Vite; exact-pinned dependencies, `npm audit` clean): token telemetry page with category counters, hourly series by vendor and SKU, source selector, weekday-by-hour heatmap, sources and freshness, and a reconciliation breakdown. Never adds sources; unknown shows "not reported"; accessible labels on charts and tables. OIDC sign-in (authorization code + PKCE, session storage) is written but untested against a real identity provider. A dev-only mock (`?mock=1`) is excluded from production builds.
- API serves the built web app same-origin (`CFA_WEB_DIR`), a public `GET /config.json`, `CFA_OIDC_CLIENT_ID`, and security headers (CSP, nosniff, no-referrer). The container image is now multi-stage and builds from the repository root; CI runs the web checks as an image build stage. Dependabot npm, pip and Docker blocks now point at `apps/web` and `apps/api`.
- ADR 0010 (accepted scope): vendor APIs for Claude Code, OpenAI Codex, Perplexity, Google Gemini and GitHub Copilot; cloud APIs for Bedrock, Foundry and Vertex AI; Microsoft Copilot via Graph and Viva. Nothing implemented or verified. Risks R-16 to R-18 added.
- AI economics redesign proposal in `docs/economics/` (current-state assessment and gap analysis with KEEP, REFACTOR, REMOVE, BUILD; target architecture; canonical data model aligned to FOCUS 1.4; connector framework with a documentation-sourced capability matrix; calculation engine; UX; four-phase roadmap), ADR 0011 (proposed), proposed requirements REQ-013 to REQ-022, and risks R-19 to R-23. No code changed.
- Phase 1 slice 1 (ADR 0011 accepted): economics calculation library in `apps/api/src/cfa_tokenomics/econ`. Exact-decimal arithmetic (floats refused), basis (observed, estimated, assumed) propagated through every result, unknown inputs give unknown results, mixed currencies refused, content-hashed nodes recording formula, inputs and basis for the explain view. Implements AI cost estimate, total and run cost, unit economics, business value (capacity and cashable), ROI, payback on run cost, price models (linear, usage, tiered), marketplace fee, required price, margin, break-even, commitments, driver-based scenario evaluation, and tornado and grid sensitivity. 37 tests reproduce the design's worked example exactly. Not yet connected to data or the API. `AGENTS.md` updated for the new scope.
- Phase 1 slice 2: economics core schema (migration `0005`): tenants, business units, customers, environments, applications, workloads, application customers, price books and entries, value assumptions, scenarios and drivers, calculation nodes and edges. Row-level security is forced on every table, keyed to a transaction-local tenant setting, and fails closed when none is set. Foreign keys include the tenant so cross-tenant references are impossible even for a privileged writer. Assumption history and calculation nodes are append-only (insert and select policies and grants only). Money is exact `NUMERIC`. Repository functions for tenants, applications, versioned assumptions (a rationale is required), non-overlapping price entries, scenarios, and saving or loading calculation trees with content-hash tamper detection. `/readyz` now refuses a database role that can bypass row-level security (`CFA_ALLOW_RLS_BYPASS` for dev only). `python -m cfa_tokenomics.admin` creates tenants and prints the runtime role grants. Existing usage, role and audit tables are not yet tenant-isolated.
- Node ids now hash the exact digits, basis mix, label and note (not the ambient decimal context), so a stored figure whose basis or wording was changed is detected.
- Phase 1 slice 3: FOCUS cost layer (migration `0006`) and manual import. Pure CSV parser (exact decimals, rejects rather than coerces or rounds, gzip with size limits, extensions preserved), importer (once per file, one transaction, strict by default with `--allow-partial`, supersession of revised windows per billing account and sub account, finality, raw file kept with row lineage), `NUMERIC(38,18)` cost records, append-only history, per-currency cost summary that keeps billed and effective cost separate. `python -m cfa_tokenomics.admin import-focus`. Shared database fixtures moved to `tests/conftest.py`. Synthetic files only; no real export has been imported; CSV only.
- Phase 1 slice 4: allocation (migration `0007`). Pure engine with exact largest-remainder splitting in integer units (independent of decimal precision), five methods (direct, tag, fixed percent, even, proportional with versioned drivers), ordered rules where a matching rule that cannot be applied falls through and the unallocated reason is kept. Append-only versioned rules, drivers and allocated slices; runs are one transaction, skipped when identical, and "latest" is decided by a sequence number. Reports keep allocated, unallocated and not-yet-allocated apart per currency with a coverage ratio; `verify_allocation`; `admin allocate`. FOCUS 1.3 provider split-allocation columns stored typed and counted. Bugs found and fixed by the tests: decimal-context rounding of 38-digit amounts, a join that counted a cost line once per slice, and clock-tied run ordering.
- FOCUS 1.5 readiness (docs/economics/08): declared version `1.5` accepted; `ServiceProviderName` required for declared 1.4 and 1.5; `ProviderName` alias confirmed and `PublisherName` kept as an extension; `PricingCurrency` may hold a provider unit; the 1.5 identity columns are dropped by default. FOCUS 1.5 is not ratified.
- `api-ci.yml` workflow (lint, tests, image build; Actions pinned by SHA).
- Accepted ADRs 0004 (stack), 0005 (container packaging and marketplace), 0006 (persistence) and a [marketplace gap analysis](docs/marketplace.md).
- Phase 1 slice 5: economics HTTP API (`economics_api.py`). Applications, versioned assumptions with history, allocation rules, drivers, runs and the coverage summary, scenario evaluation with optional tornado and saving, and `GET /v1/explain/{node_id}` returning the verified calculation tree down to its inputs. New permissions `economics:read` (reader, user, admin) and `economics:write` (user, admin). Every route runs in a tenant-scoped session (`CFA_DEFAULT_TENANT_ID`), so row-level security decides visibility; authentication runs before the tenant session opens; writes leave audit events. Decimals must be strings or integers (floats are refused). A tampered stored node returns 500, never a silently wrong figure. Not done: per-application access scoping (R-25), a Parquet or file-upload route, and any screens. Tested on synthetic data against a restricted database role.
- Phase 1 slice 6: application economics screens in `apps/web`. Portfolio, application detail (Economics, Value model, Cost and allocation, and the telemetry page as the Usage tab), a basis badge on every figure with a banner stating the share resting on assumptions, capacity and cashable value side by side, and an Explain drawer down to the inputs. The value model editor requires a reason for every change and keeps history; an unknown driver yields an unknown result and a missing one stops the calculation. Hash routing, no new dependencies. Tested with 39 unit and render tests and checked against the real API on synthetic data as admin and as reader. Brand, fonts and logo remain pending approval; no scenario, pricing or FinOps screens yet.
- Phase 1 slice 7: the legacy tables are tenant-isolated and the ledger is projected into normalized usage facts. Migration `0008` adds `tenant_id`, forced row-level security and tenant-scoped keys to the role, grant, audit, request, aggregate and checkpoint tables; the audit log becomes append-only; `tenant_id` defaults to the session's tenant so a write with no tenant is refused. Existing rows have no tenant and nothing guesses one: they stay invisible and `/readyz` reports `legacy_tenant_unassigned` until `python -m cfa_tokenomics.admin assign-legacy-tenant TENANT_ID` assigns and finalizes (an empty install is finalized by the migration). Usage routes and authorization now run in the installation's tenant, so `CFA_DEFAULT_TENANT_ID` is required (`/readyz`: `tenant_not_configured`). Migration `0009` adds `usage_facts` (exact decimals, unit, basis, quality, revision, source row) and `project-usage` fills it idempotently; unknown categories produce no fact. Tested as a restricted role and as a non-superuser table owner; not run against a real install with data (R-26).
- Phase 2 preparation: [vendor API research](docs/economics/09-vendor-api-research.md) for Anthropic and Claude Code, OpenAI and Codex, GitHub Copilot, Perplexity, Google Gemini and Vertex AI, Microsoft 365 Copilot and Viva, AWS (Cost Explorer, Data Exports, Bedrock) and Azure (Cost Management, Foundry), compiled from official vendor pages on 2026-11-10. Records endpoints, permissions, limits, revision windows and privacy flags, corrects the connector matrix, and lists what is still not found. Documentation only: no API was called and no connector exists. Updates R-16 and R-21.
- Phase 2: AWS Data Exports and Azure Cost Management export connectors (`connectors/`). They read a FOCUS CSV export (plain or gzip) from the customer's S3 bucket or Blob container with read-only access through the platform's own identity (no credential is configured, stored or logged; a SAS token or secret in the settings is refused), join a run's parts into one logical file so they cannot supersede each other, import only the newest run of each period, skip an unchanged run without downloading it, defer a half-written one, apply each cloud's own revision window for finality, and refuse (not truncate) oversize runs. New admin commands `connector-add`, `connector-check`, `connector-run` and `connector-status`. New pinned dependencies `boto3`, `azure-storage-blob` and `azure-identity` (`pip-audit` clean). Tested on synthetic exports with stubbed storage; not run against a real export (R-27); no scheduler, streaming import or Parquet yet.
- Export sanitizer (`python -m cfa_tokenomics.sanitize`): copies a real FOCUS CSV export (plain or gzip, a file or a folder) into a form safer to share for testing. An allow-list passes only known non-identifying columns and drops every other column (extension columns, descriptions, the 1.5 identity columns); account, resource and invoice identifiers become consistent keyed pseudonyms with a random salt that is never printed or recorded (an optional private salt file keeps them stable across runs); emails, ARNs, GUIDs, 12-digit account numbers and IPv4 addresses in kept text and tags are scrubbed; an optional exact `--scale` hides absolute spend; a final leak check deletes the output if an email or ARN survives, and a failure on any file leaves no partial output. Folder layout is kept. Tested on invented stand-ins for sensitive values, never on a real export. It reduces what a file reveals but does not prove anonymity: the owner reviews the output first.
- FOCUS 1.5 AI model billing: `GET /v1/cost/ai-tokens` and `focus/ai.py` report tokens, cost, effective cost per million tokens, input-to-output ratio and cache hit rate by provider, model, token direction and cache action from imported FOCUS rows, following the draft's queries and caveats (exact unit `Tokens`, corrections excluded from tokens, cache hit rate over all input rows, rows without a model or direction counted not guessed, an unknown rate is null). Checked against the unpublished 1.5 working draft supplied by the owner (neither supplied file is stored here): the readiness note now records what the draft confirms (four new Conditional columns, `SkuPriceDetails` model and token properties and allowed values, no double counting of cached tokens) and corrects (the SKU Price dataset is a preview; the mandatory column list is longer than the importer requires). New [tokenomics vocabulary](docs/economics/10-tokenomics-vocabulary.md) note on the seven-layer stack and Big-T notation, which contain no formulas. Tested on synthetic rows only; adds R-28.
- Vendor research: the OpenAI Admin API OpenAPI file supplied by the owner (not stored here) replaces the Codex *not found* items in the [vendor API research](docs/economics/09-vendor-api-research.md): the unified Daily Usage endpoint (credits, native USD, estimated cost and API-priced text tokens, kept separate; eventually consistent with no stated correction window; per-user rows carry email), the Codex-only usage endpoint deprecated for retirement on 2026-12-15, per-user monthly usage against caps, and the Compliance API's content and delete endpoints (never connect). Documentation only; no connector built.
- ADR 0012 (accepted as read from the owner's reply): vendor sources run in aggregate mode by default, per-user mode is a recorded administrator opt-in with keyed pseudonyms (`privacy.py`, HMAC-SHA256 truncated to 128 bits, customer-held key, never stored or logged), and content-bearing sources are never connected. Known gap recorded: the raw FOCUS copy keeps the 1.5 identity columns. Synthetic sample sets (`python -m cfa_tokenomics.samples`): one fictional cast across AWS and Azure FOCUS-style exports, the OpenAI Daily Usage API and the Anthropic analytics shapes, deterministic and clearly marked synthetic. The samples import through the cost-export connectors, feed the AI token view and tag allocation in tests. The AI token view now includes AI-category correction rows that carry no token quantity, so a correction's cost is never hidden.
- Anthropic connector (`connectors/anthropic.py`, aggregate mode): reads the Admin API's usage and cost analytics (beta) with a read-only credential given as `env:` or `file:` reference (never a value; the host is fixed), groups only by model, workspace, tier, speed and context window and never by person, paces under 60 requests per minute with bounded retries and cursor-expiry restarts, stores usage in the usage ledger and cost as FOCUS-shaped rows (cents converted exactly, token counts joined, `ModelId`, `TokenDirection` and `TokenCacheAction` set), leaves days newer than `data_refreshed_at` for later, and sets finality from the 7-day-after-month-end window. `BilledCost` is a pre-credit amount and says so. `per_user` mode is refused until its storage exists. The admin connector commands now dispatch through a registry. Tested against a fake server built from the synthetic samples; not run against the real API (R-29).
- Codex and ChatGPT Enterprise connector (`connectors/codex.py`, aggregate mode): reads the unified Daily Usage API with `group=workspace` and a read-only Admin key given as an `env:` or `file:` reference (fixed host; per-user mode refused). Credits and native USD stay separate and are never converted: native USD is stored as cost with basis `observed`, credit-priced usage only where the source gives an estimate, with basis `estimated` and the exact credits kept in `x_Credits`, in separate sub-accounts so one stream never supersedes the other. API-priced text tokens go to the usage ledger; a missing field is unknown, a reported zero stays zero. Amounts are parsed as exact decimals from the response text. Finality comes from the window with an assumed 30-day correction window. The FOCUS importer gained a validated `basis` parameter, the HTTP paging, pacing and retry code is shared with the Anthropic connector, and the synthetic workspace rows now carry client and model breakdowns. Tested against a fake server and the samples; not run against the real API (R-30).
